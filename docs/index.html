banana-brain technical documentationDocumentation technique de banana-brain

C++20 neural network library on top of libutils: one NeuralNetwork for several kinds of networks (layered, brain, banana), their training and the dataset tools. Version v1.0.0 is the architecture only: every signature exists, the logic comes next.Bibliothèque C++20 de réseaux de neurones basée sur libutils : un NeuralNetwork pour plusieurs types de réseaux (par couches, cerveau, banane), leur entraînement et les outils de jeux de données. La version v1.0.0 est l'architecture seule : chaque signature existe, la logique vient ensuite.

1. Overview1. Vue d'ensemble

banana-brain is a static C++20 library (libbanana-brain.a) built on libutils. Everything is in the namespace brain:: (tools in brain::tools::). A brain::NeuralNetwork owns one network (brain::INetwork) created by init<NetworkType>(), configures it (seed, size, activation / loss functions, learning rate), trains it (automatic rounds or a manual loop) and runs it (exec).banana-brain est une bibliothèque statique C++20 (libbanana-brain.a) basée sur libutils. Tout est dans le namespace brain:: (les outils dans brain::tools::). Un brain::NeuralNetwork possède un réseau (brain::INetwork) créé par init<NetworkType>(), le configure (graine, taille, fonctions d'activation / de perte, taux d'apprentissage), l'entraîne (tours automatiques ou boucle manuelle) et l'exécute (exec).

Status (v1.0.0): architecture only. Every class, function and exception code exists with its final signature and an empty body (/* Nothing */); the logic is planned for the next versions. The behaviors described below are the intended ones.État (v1.0.0) : architecture seule. Chaque classe, fonction et code d'erreur existe avec sa signature finale et un corps vide (/* Nothing */) ; la logique est prévue pour les versions suivantes. Les comportements décrits ci-dessous sont ceux attendus.

2. Install & integrate2. Installer & intégrer

2.1 Packages2.1 Paquets

The packages follow the libutils layout: a global package pulling the headers and the optimized library, one library package per build mode (-op, -db, -as) and the matching CMake configuration (-dev-op, -dev-db, -dev-as). Each library package requires the libutils package of the same mode. The -pre suffix is the unstable channel. setup.sh registers the package repository (tsukini22.github.io/banana-brain) and installs the global package.Les paquets suivent l'organisation de libutils : un paquet global qui tire les en-têtes et la bibliothèque optimisée, un paquet de bibliothèque par mode de build (-op, -db, -as) et la configuration CMake correspondante (-dev-op, -dev-db, -dev-as). Chaque paquet de bibliothèque requiert le paquet libutils du même mode. Le suffixe -pre est le canal instable. setup.sh enregistre le dépôt de paquets (tsukini22.github.io/banana-brain) et installe le paquet global.

curl -fsSL https://raw.githubusercontent.com/TsukiNi22/banana-brain/main/setup.sh | bash -s          # --pre, --no-install, --no-sudo
sudo dnf install libbanana-brain                 # libbanana-brain-dev + libbanana-brain-op
sudo dnf install libbanana-brain-db libbanana-brain-as   # Debug / Asan modes (+ libutils-db / libutils-as)
sudo dnf install mingw64-libbanana-brain         # Windows (MinGW sysroot)
sudo apt install libbanana-brain
sudo apt install libbanana-brain-db libbanana-brain-as
cmake -S . -B build
sudo cmake --build build --target install_release --parallel $(nproc)   # Debug, Asan & Optimized (install: Optimized only)

find_package(banana-brain 1.0.0 CONFIG REQUIRED)                    # finds libutils (utils::utils) too

The library follows the CMAKE_BUILD_TYPE of the project: Debug → libbanana-brain_debug.a, Asan → libbanana-brain_asan.a, anything else → libbanana-brain.a. The installed configuration stops with the name of the missing package. On Windows the same CMake works with a MinGW toolchain (cmake/toolchain/mingw-w64.cmake, or mingw64-cmake on Fedora) and the mingw64-libbanana-brain* packages of the MinGW sysroot (no Asan with MinGW).La bibliothèque suit le CMAKE_BUILD_TYPE du projet : Debug → libbanana-brain_debug.a, Asan → libbanana-brain_asan.a, autre → libbanana-brain.a. La configuration installée s'arrête avec le nom du paquet manquant. Sous Windows le même CMake fonctionne avec une toolchain MinGW (cmake/toolchain/mingw-w64.cmake, ou mingw64-cmake sur Fedora) et les paquets mingw64-libbanana-brain* du sysroot MinGW (pas d'Asan avec MinGW).

#define _Exception
#include <utils/utils.hpp>
#include <brain/brain.hpp>

brain::NeuralNetwork network;
network.init<brain::NetworkType::Layered>(3, 8);   // 3 layers of 8 neurons
network.size(2, 1);                                   // 2 inputs, 1 output
network.seed(42);
network.internalActivationFunction(brain::ActivationFunction::Sigmoid);
network.internalLossFunction(brain::LossFunction::MSE);
network.weightInit();
network.train(brain::UIType{100}, inputs, expected, [](const brain::Values& out, const brain::Values& want) { return brain::FType{0.0}; });
network.freeze();
brain::Values outputs = network.exec({0.0, 1.0});

4. Networks4. Réseaux

brain::INetwork is the interface used by NeuralNetwork: memory (load / unload, failsafe), execution (inputs, apply, backpropagation(coef) / backpropagation(coefs)), setup (weightInit, biasInit) and neurons() (<layers, neurons>). brain::ANetwork holds the shared state (last inputs, loaded flag) and a default empty init_(); every constructor calls init_() at its end to create the neurons.brain::INetwork est l'interface utilisée par NeuralNetwork : mémoire (load / unload, failsafe), exécution (inputs, apply, backpropagation(coef) / backpropagation(coefs)), mise en place (weightInit, biasInit) et neurons() (<couches, neurones>). brain::ANetwork porte l'état commun (dernières entrées, drapeau chargé) et un init_() vide par défaut ; chaque constructeur appelle init_() à sa fin pour créer les neurones.

5.2 Training5.2 Entraînement

train(round, inputs, expected_outputs, backpropagation) runs n rounds over the dataset; train(loss, ...) runs until the mean loss is under the given rate (checked after each round). The hook receives the outputs and the expected ones and returns one coefficient (BackpropagationFn) or one per output (BackpropagationsFn), between -1 and 1: 1 = perfect, -1 = totally false, above / under for a massive change. The first argument must be exactly a brain::UIType (rounds) or a brain::FType (loss): a deleted template refuses any other type (train(10, ...) doesn't compile, train(brain::UIType{{10}}, ...) does).train(round, inputs, expected_outputs, backpropagation) fait n tours sur le jeu de données ; train(loss, ...) tourne jusqu'à ce que la perte moyenne passe sous le taux donné (vérifié après chaque tour). Le hook reçoit les sorties et celles attendues et renvoie un coefficient (BackpropagationFn) ou un par sortie (BackpropagationsFn), entre -1 et 1 : 1 = parfait, -1 = totalement faux, au-delà pour un changement massif. Le premier argument doit être exactement un brain::UIType (tours) ou un brain::FType (perte) : un template supprimé refuse tout autre type (train(10, ...) ne compile pas, train(brain::UIType{{10}}, ...) oui).

The manual loop exposes each step: load() (memory, GPU planned), inputs(values), apply(), loss(output, expected) / loss(outputs, expected) (mean), backpropagation(coef) / backpropagation(coefs), unload().La boucle manuelle expose chaque étape : load() (mémoire, GPU prévu), inputs(values), apply(), loss(output, expected) / loss(outputs, expected) (moyenne), backpropagation(coef) / backpropagation(coefs), unload().

5.3 Usage, freeze, files5.3 Usage, gel, fichiers

exec(inputs) runs the network without touching its content: it is the only call allowed once the network is frozen (freeze() of utils::type::Freezable, FrozenNetwork error for the others). save(path) / load(path) store and restore a network, clear() removes it and resets the training state.exec(inputs) exécute le réseau sans toucher à son contenu : c'est le seul appel permis une fois le réseau gelé (freeze() de utils::type::Freezable, erreur FrozenNetwork pour les autres). save(path) / load(path) stockent et restaurent un réseau, clear() le supprime et remet l'état d'entraînement à zéro.

7. Errors7. Erreurs

The errors are libutils exceptions (utils::exception::ErrorException, WarningException...) with the codes of the library, utils::exception::ExternalCode::<code>, generated at the build from cmake/config/exceptions/brain.json into include/brain/exception/generated_external_exception_header.hpp and installed with the headers. Catch utils::exception::IException and print formated().Les erreurs sont des exceptions libutils (utils::exception::ErrorException, WarningException...) avec les codes de la bibliothèque, utils::exception::ExternalCode::<code>, générés au build depuis cmake/config/exceptions/brain.json dans include/brain/exception/generated_external_exception_header.hpp et installés avec les en-têtes. Attraper utils::exception::IException et afficher formated().

8. Build, tests & CI8. Build, tests & CI
